# Releasing

What is ready, and what is still to do, before Silverpoint's first public release (1.0.0).

## Done

- **Name:** Silverpoint (renamed from the working title Safelight).
- **Application ID:** `app.silverpoint.camera`. Final: it cannot change after the first store upload.
- **Logo:** silver grains spiralling into one point of light. Generated by `scripts/make_logo.py`, which writes the adaptive icon's background, foreground and themed monochrome layers.
- **Look names:** original names; no film or camera brand names in the app (what inspired each look is in [RECIPES.md](RECIPES.md)).
- **Start-up film:** made with Remotion in `motion/` (see [DEVELOPMENT.md](DEVELOPMENT.md#start-up-film-remotion)).

## Renaming the app again

The name sits in user-facing text (`strings.xml` `app_name`, the intro, Settings, the permission card, Diagnostics), in file locations (`GallerySaver.RELATIVE_PATH` = `DCIM/Silverpoint`, `Download/Silverpoint/diag_…`), in EXIF and DNG descriptions, and in code identifiers (package `app.silverpoint`, `SilverpointApp`, `SilverpointTheme`, `SILVERPOINT_*` variables). List them with `git grep -n -i silverpoint`. The application ID cannot change once published.

## Signing

Release builds are signed only when these are set, as environment variables or in `~/.gradle/gradle.properties` (never in the repository):

| Variable | Value |
|---|---|
| `SILVERPOINT_KEYSTORE` | path to the keystore file |
| `SILVERPOINT_KEYSTORE_PASSWORD` | keystore password |
| `SILVERPOINT_KEY_ALIAS` | key alias |
| `SILVERPOINT_KEY_PASSWORD` | key password |

Make an upload key once, and back it up together with its passwords. If it is lost, updates cannot be signed (Play App Signing can reset an upload key; a sideloaded APK's key cannot be replaced):

```bash
keytool -genkeypair -v -keystore upload.jks -keyalg RSA -keysize 4096 -validity 10000 -alias upload
```

Then:
- `./gradlew assembleRelease` builds a signed APK in `app/build/outputs/apk/release/`.
- `./gradlew bundleRelease` builds an App Bundle for Google Play.

`*.jks` and `*.keystore` are gitignored.

## Versioning

- **Version numbers:** `versionName` follows [Semantic Versioning](https://semver.org/), and `versionCode` goes up by one with every build you publish. Both are in `app/build.gradle.kts`.
- **Changelog:** move the `[Unreleased]` items in [CHANGELOG.md](../CHANGELOG.md) under the new version with the date.
- **Tag and release:** tag `vX.Y.Z` and attach the signed APK to a GitHub Release.

## Store listing checklist (Google Play)

- **Device catalogue:** the app targets the Galaxy S25 Ultra. Either restrict the device catalogue to it, or say clearly in the listing that other phones are untested. Set `uses-feature android.hardware.camera.capability.raw` (in `app/src/main/AndroidManifest.xml`) to `required="true"` if the store should hide the app from phones without RAW.
- **Data safety:** the app has no internet permission, no analytics and no accounts. Photos, DNGs and Diagnostics reports stay on the phone unless the user shares them. Photos carry no location in EXIF.
- **Privacy policy:** Play requires a URL even when nothing is collected. A short page saying the above is enough.
- **Permissions to explain:**
  - camera;
  - vibration;
  - a foreground service of the "special use" type, which finishes developing photos after the app is closed. Play asks for a justification of the special-use type.
- **Screenshots:** the dev-only screenshot tests render every screen at the S25 Ultra's size (see [DEVELOPMENT.md](DEVELOPMENT.md#dev-only-tools)). Real device screenshots are better for a listing.
- **Target API:** Play requires a recent `targetSdk` (currently 36). Check the current requirement before uploading.
