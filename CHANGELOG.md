# Changelog

All notable changes to this project are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project aims to follow [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Changed
- **Looks renamed** to original names, with no film or camera brand names anywhere in the app (for example Classic Chrome is now Reportage, Velvia Vivid is Vivid Slide, CineStill 800T is Tungsten 800); the full list and what inspired each look are in [docs/RECIPES.md](docs/RECIPES.md). The inspiration references moved out of the app's recipe file into that document. Starred looks saved under the old names are not carried over.
- **Test photos** replaced with a new scene (a sofa, cushion and plants by a window): RAW crops for the pipeline tests with their Lightroom reference (neutral rendering against Lightroom: mean ΔE2000 3.1 on the window-lit wall, 2.9 on the cushion; deep shadows +3.7 L*, as documented), and a neutral development of the whole frame for the screenshot tests.
- **Renamed** to Silverpoint (from the working title Safelight):
  - application ID `app.silverpoint.camera`;
  - code package `app.silverpoint`;
  - Gallery album `DCIM/Silverpoint`;
  - Diagnostics folder `Download/Silverpoint`;
  - environment variables `SILVERPOINT_*`.

### Removed
- The five extra presets added in 0.9.5; the engine support for the Lightroom settings they used stays.

### Added
- **New icon:** silver grains spiralling into one point of light. It has adaptive and themed (monochrome) layers, generated by `scripts/make_logo.py`.
- **First-launch start-up film**, made with Remotion (`motion/`). Grains swirl into the mark, and its centre ignites with a flash, a light streak, a shockwave and a haptic tap. The mark then glides into the first tutorial page as the page fades in. Tap to skip; it is skipped when system animations are off. The system splash is now plain black, so the film starts from black.

## [0.9.9] - 2026-10-10

Release preparation.

### Changed
- **Release builds** are shrunk with R8 (the APK goes from about 31 MB for debug to about 2.6 MB) and signed from environment variables when a keystore is configured ([docs/RELEASING.md](docs/RELEASING.md)).
- **Documentation rewritten for the public:**
  - new README, [DEVELOPMENT](docs/DEVELOPMENT.md) and [RELEASING](docs/RELEASING.md);
  - the decision log and the device checklist became [DESIGN_DECISIONS](docs/DESIGN_DECISIONS.md) and [DEVICE_TESTING](docs/DEVICE_TESTING.md);
  - internal working notes and the original brief removed;
  - third-party notices corrected.
- **Credits:** the README credits Claude (Anthropic) for writing the app.
- **Smoother camera screen:**
  - the screen no longer recomposes on every orientation change while the level is off;
  - the shutter and ISO dials stop re-measuring and re-formatting their labels on every frame;
  - the develop spinner turns without recomposing;
  - lens-derived values are worked out once per lens.
- **Preview renderer:** shader locations are looked up once instead of on every frame, and the histogram reuses one buffer.
- **Faster start-up:** the look-preview tables are baked off the look thread, so the viewfinder's own look is not queued behind them. Flicking through looks no longer queues stale table bakes.
- **Ultra HDR gain map:** no longer allocates an object per pixel.

### Fixed
- **Last photo:** it is kept when the camera screen closes while the photo is still developing, so the gallery button shows it on return.
- **GPU developer:** one that fails to start no longer leaves its thread and EGL context behind.
- **RAW feature name:** the manifest declared it as `android.hardware.camera.raw`; it is now the real `android.hardware.camera.capability.raw`.
- **Silent failures:** a camera-control, tap-to-focus or preview-frame failure is now logged instead of silently swallowed.
- **CI:** the motion test is excluded from normal runs like the screenshot test, so CI does not download Robolectric's Android jar.

### Removed
- Unused code (an old swatch drawing, unused camera-controller functions, burst arrival times, an unused EV label), unused imports, and the unused Compose tooling and ViewModel-Compose dependencies.

## [0.9.8] - 2026-10-10

- Two motion fixes from a device screen recording. Pro mode: the lens row and the open dial share one animated slot, so opening, switching and closing a dial is one movement (crossfade while the height eases over 240 ms) instead of the lens pill shrinking while the dial popped in; the darker fade behind a dial eases in with it. Look selector: the sheet keeps one height (86% of the screen) for every tab instead of resizing to each tab's looks, which made the tabs jump away from the finger; a new tab starts scrolled to its top. Dev-only `MotionTest` saves transitions frame by frame.

## [0.9.7] - 2026-10-09

- Fixes from the first phone test of 0.9.6. Haptics now play through the vibration motor (composition primitives with predefined fallbacks, hardware-feedback usage) instead of the view, which Android silently dropped; new Settings → Haptics switch. Look previews are live: the preview renderer draws the camera into each visible look card and circle through that look's table, about 30 times a second at the card's own resolution (0.9.6 refreshed a 144 × 192 still every 4 s). New Settings → Live look previews switch; off, and before the first live frame, the looks are shown on a bundled sample picture (drawn, regenerated by `scripts/make_look_sample.py`). The control deck fits the S25 Ultra's real screen (about 384 × 832 dp with system bars): smaller quick-looks row (the look's name now shows briefly over the picture), shutter row, tabs, Pro buttons and dial; the lens pill hides while a Pro dial is open; a darker fade behind open dials. Screenshot tests now render at that size with the system bars drawn in, plus 412 dp, short-screen and 115% text variants.

## [0.9.6] - 2026-10-09

- Camera screen redesigned to be less claustrophobic. The viewfinder is full width in the photo's shape with nothing over it unless asked; Pro controls cover about 16% of it with a setting open (about 45% before). New: flash (Off, Auto, On; precapture metering, never merged); four shapes (3:4, 4:5, 1:1, 9:16; the JPEG and its gain map are cropped, the DNG keeps the whole sensor); Pro mode as round value buttons with Samsung-style ruler dials (snapping, fling, whole-stop marks); a haptic vocabulary (detents, end stops, shutter, capture confirmed, focus lock, errors, timer); a look selector with live previews of the scene through every look, tabs by kind and stars; a quick row of starred looks. The top bar is Settings, Flash, Timer, Shape and Viewfinder aids (grid, level, histogram, zebras, peaking in one row). Develop timings moved to Settings → Last photo; the histogram is off by default; self-timer gains 5 s.

## [0.9.5] - 2026-10-09

- New engine support for more Lightroom settings: red/green/blue channel curves, Color Grading midtone and global wheels with Blending, the Calibration panel's primaries, the recipe's own Sharpening amount and edge Masking, and the vignette's Midpoint and Feather. The common corrections from `docs/LIGHTROOM_MATCHING.md` now apply to every recipe without its own measurement (shared tone curve; pinks −7% saturation, oranges 8° towards red, blues +6% and 3.5° towards cyan); black and white gets tone only. New `RecipeIdentityTest` checks that the corrections keep every recipe's character (effect direction 0.96–1.00, size 0.94–1.06).

## [0.9.4] - 2026-10-09

- Recipes matched to Lightroom exports of the same RAW files. A per-recipe correction (`match`: tone curve, per-hue chroma and hue, shadow/highlight tint) is fitted from photo pairs and baked into the look table; fitted for California Summer, Reportage, Grit 400 and Vivid Slide (mean ΔE2000 against Lightroom 3.65 / 2.86 / 1.66 / 3.02 → 1.11 / 1.18 / 1.10 / 0.96), the average tone correction for the other 17. Photos are now sharpened and colour-smoothed like Lightroom's RAW defaults (fewer blue/orange specks on fine detail, crisper edges). Grain redesigned to Lightroom's: finer, not blocky, even across shadows and highlights, amount^0.67. Fix: a non-ASCII character in a shader comment, which strict GLSL compilers reject. Dev tools: `scripts/match_samples.py` and `RecipeMatchFitTest` (fitting), `scripts/gpu_parity.py` with `GpuParityDumpTest` (runs the real shaders on a desktop OpenGL such as Mesa's llvmpipe and compares them with the CPU reference, so shader changes are checked before reaching a phone).

## [0.9.3] - 2026-10-09

- Redesigned interface in One UI's dark style with a darkroom-safelight orange accent. Fixes: Settings text was black on a dark background (the theme followed the phone's light/dark setting and nothing set the text colour); in Pro mode the shutter, gallery and AUTO/PRO buttons were squeezed off the screen, so Pro mode could not be left. The viewfinder now takes only the space the controls leave; Pro values and sliders float over its bottom edge; PHOTO and PRO tabs are always visible, and swiping the viewfinder switches between them. New: icon top bar (timer with seconds in the clock, grid, level, histogram, zebras, peaking), a One UI zoom pill, an EV button with its own slider, One UI-style sliders (white balance and tint tracks show their colours), recipe swatches showing each look on skin, foliage and sky, a processing ring round the gallery thumbnail, haptics, Settings with a large collapsing title and grouped cards, a restyled recipe sheet, introduction and Diagnostics, light status-bar icons and a black launch window. Dev-only screenshot tests render every screen on the JVM (Robolectric + Roborazzi) when `SILVERPOINT_SCREENSHOTS` is set.

## [0.9.2] - 2026-10-09

- Fixes from a second review. Pro-mode tint now follows Lightroom (+tint makes the photo magenta; it made it green before) on Adobe's tint scale. Lenses are read again once the camera permission is granted, so photos no longer fail ("sensor has no colour matrix") and autofocus is not missing in the first session after install. A photo whose frames were captured is always finished, even if the camera screen is closed meanwhile, and the "Developing photos" service can no longer get stuck or be stopped while a new photo starts. Merged bursts use one locked exposure for all frames. The GPU developer is retried once after a failure and the timing line says why it failed. In full manual with a shutter longer than 1/15 s, the preview raises its ISO to stay as bright as the photo (it was up to 2 stops darker). Smaller: the level line follows landscape, 1/4 s is labelled 1/4 (not 0.3 s), EXIF writes 0.4 s exactly, recipe curves with repeated inputs are rejected at load and in CI, Pro mode's shutter hint no longer suggests that merging lengthens exposures, and closing a renderer twice can no longer hang.

## [0.9.1] - 2026-10-09

- Fixes from a review of the untested Android code: camera buffers stay valid while a merge or copy still reads them; camera errors release the preview renderer; the develop service starts at the shutter press and stops itself; burst frames pair with their metadata by order when timestamps differ; noise reduction, edge and lens-shading settings reach the physical lens; capture timeouts grow with the exposure; closing the camera when leaving waits for the camera thread; switching to a lens with a different preview size waits for the new viewfinder.

## [0.9.0] - 2026-10-09

- Ultra HDR JPEGs (gain map from the quarter-resolution luminance, up to 2 stops of highlight headroom, via Android's `Gainmap` API); Silverpoint's own EXIF writer, which keeps the Ultra HDR index valid; the GPU self-test also checks the gain-map luminance. Docs: rewritten README, `docs/DEVICE_TESTING.md` (what to test on the phone), `docs/DESIGN_DECISIONS.md`, updated ARCHITECTURE.

## [0.4.0] - 2026-10-09

- Multi-frame merge (Auto in low light, Always, Off): bursts of 6 RAW frames aligned per tile and averaged with noise-aware weights that reject moving objects; merged frames keep 4 extra bits of precision. Photos develop in a background queue (up to 3 waiting) kept alive by a foreground service, so the shutter is free again right after a shot. Merge is skipped when the phone runs warm.

## [0.3.0] - 2026-10-09

- All four rear lenses (0.6, 1, 3, 5) with fast switching; Pro mode with manual ISO, shutter, focus and Kelvin + tint white balance (exact in the developer), emulated shutter/ISO priority; tap to focus and meter, double tap to reset; self-timer (2 s, 10 s); optional DNG next to each photo.

## [0.2.0] - 2026-10-09

- Live recipe preview (OpenGL: recipe look table, vignette, animated grain, zebras, focus peaking, histogram) with automatic fallback to the plain camera preview; recipe strip with favourites (long-press to star) and a full recipe sheet with descriptions; settings screen (viewfinder aids, merge mode, Ultra HDR, DNG option, about); first-launch introduction; grid and level overlays. Settings persist between launches.
- Recipe engine (Phase 2): every key in `recipes.json` now affects the photo. A 33³ look table per recipe (tone sliders, contrast, curve, HSL bands, black-and-white mixer, split toning, dehaze), Clarity and Texture from a blurred quarter-resolution luminance image, vignette, and film grain that is identical on the CPU and the GPU. New compute passes `lowres.comp` and `blur.comp`; shaders share code through `common.glsl`. The GPU self-test gains an every-control case and a black-and-white case. See `docs/RECIPE_ENGINE.md`.

## [0.1.2] - 2026-10-09

- Each Diagnostics run gets its own folder, `Download/Silverpoint/diag_<run ID>/`, holding the DNGs and the report. DNGs are named `<run ID>_<lens>_<route>.dng` (for example `main-1x`, `tele-5x`) and carry the run and lens details in their ImageDescription tag. The report (`probeVersion` 4) records the run ID, folder and a `files` list mapping each DNG to its lens, focal length, ISO and shutter.
- Base look checked in three more scenes (daylight outdoor, daylight indoor, warm low light) without refitting: mean ΔE2000 2.2 to 3.4 against Lightroom. `scripts/make_fixture.py` now aligns full-size exports from Lightroom for Android, and `LightroomFitTest` prints per-hue errors for the committed values.

## [0.1.1] - 2026-10-09

- Neutral base rendering fitted to Lightroom's default (no edits; Adobe Standard for these DNGs) on a real S25 Ultra DNG: +1 EV baseline, highlight shoulder from 0.1, base S-curve, slight chroma reduction. Mean ΔE2000 against Lightroom went from 11.7 to 3.2; photos were about 1 EV too dark before.
- Test fixtures: two crops of that DNG and of the Lightroom export, with CI checks that the neutral rendering stays close to Lightroom (`LightroomMatchTest`), plus dev-only fitting and preview tools (`scripts/make_fixture.py`, `LightroomFitTest`, `PreviewRenderTest`).

## [0.1.0] - 2026-10-09

- First camera build (Phase 1): viewfinder on the main lens with OIS, ±2 EV compensation, RAW capture, development on the GPU (black level, lens shading, white balance, Malvar-He-Cutler demosaic, DNG colour matrices, exposure, saturation/vibrance, highlight shoulder, contrast and tone curve) with the Reportage recipe, upright JPEG saved to `DCIM/Silverpoint` with EXIF (recipe in UserComment).
- New modules: `:pipeline` (CPU reference developer + GL ES 3.1 compute shaders), `:recipes` (recipes.json parser), `:storage` (MediaStore saver).
- Diagnostics screen (the probe, now version 3): manual exposure sent per lens, DNGs saved with orientation, lens-switch timing, and a GPU self-test that compares the GPU developer with the CPU reference.
- CI job that compiles the compute shaders with glslang.

## [0.0.1] - 2026-10-09

Project setup and the Phase 0 capability probe.

- Project README, Apache-2.0 license, contribution and security docs.
- 21 recipes (`recipes.json`), Lightroom reference presets.
- Repository scaffolding: issue and pull request templates, CI workflow, editor config.
- Gradle project (AGP 9.4.1, Kotlin 2.4.21, Gradle 9.6.1) with `app` and `camera` modules.
- Probe v2 (report `probeVersion` 2): per-lens preview + RAW with 3A warm-up and OIS request, zoom-ratio lens switching, manual ISO/shutter check, RAW bursts of 4/8/12 held at once, one DNG per lens saved to Download/Silverpoint, and extra colour/noise metadata.
- Probe v2 results for the Galaxy S25 Ultra: OIS works per lens, preview + RAW works on every lens, zoom ratio does not switch lenses, 12-frame RAW bursts at 30 fps, manual exposure not yet honoured.
- Probe results for the Galaxy S25 Ultra (SM-S938B): 12.5 MP RAW on all four rear lenses, no 50/200 MP, ±2 EV exposure compensation. See `docs/PROBE_RESULTS.md`.
- Phase 0 capability probe: dumps Camera2 characteristics and tries RAW captures per camera, physical lens and size, then reports a go/no-go verdict as text and JSON.
